    Python Quest MVP - デプロイレビュー（第3回）¶

    シニアエンジニアによる実機レビュー URL: https://python-quest-three.vercel.app レビュー日: 2026-02-17 レビュー方法: ソースコード静的解析（バンドルJS解析） + web_fetch レビュー履歴: 第1回 B+ → 第2回 A- → 今回: A

    総合評価¶

    A（優秀） — 前回のA-から着実にステップアップ。

    教育系プロダクトとしてのMVPクオリティは十分に達成している。特にエラーメッセージの日本語化（15パターン）、チュートリアル導入、タブレット対応の折りたたみサイドバーなど、前回指摘の主要項目がすべて反映されている点は高く評価できる。子供が「つまずいて投げ出す」ポイントが大幅に減った。

    ただしA+に至らない理由として、ブラウザ実機操作での検証ができなかったため（sandbox制約）、Blocklyのドラッグ&ドロップ操作感やサウンドフィードバックの実際の体感は未確認。ソースコード上は設計が健全。

    1. 前回指摘の反映度¶

    前回の指摘 対応状況 評価
    チュートリアル導入 ✅ 4ステップのガイド付きチュートリアル実装 🟢
    コード表示常時可視化 ✅ エディタ下部に80-140pxの固定表示エリア 🟢
    エラーメッセージ日本語化 ✅ 15パターン、emoji付きで親しみやすい 🟢
    タブレット折りたたみサイドバー ✅ アイコンモード（48px）に折りたたみ可能 🟢
    フライアウト幅制限+自動閉じ ✅ 実装確認（ソース上） 🟢
    フォント14px対応 ✅ text-base クラス適用 🟢
    ワークスペースoverflow制御 ✅ 修正適用済み 🟢

    反映度: 100% — 全指摘事項が対応済み。素晴らしい。

    2. UI/UX¶

    良い点¶

    • ダークテーマの統一感: #0a0a1a ベースで全画面統一。目に優しく、ゲーム感がある
    • グラデーション活用: ヘッダー、ボタン、XPバーにグラデーションを効果的に使用
    • レスポンシブ設計: モバイル（タブ切替） → タブレット（2カラム） → デスクトップ（3カラム）の3段階
    • 折りたたみサイドバー: 円形トグルボタン（right:-14px）で直感的に操作可能
    • アイコンモード時のナビ: 📋🎯💡🏠の4アイコンで最低限のアクセスを維持

    改善余地¶

    • Press Start 2P フォント: タイトルには良いが、読みやすさが犠牲になる箇所がないか要注意
    • モバイルタブ: 「📋 情報」「🧩 エディタ」「📺 出力」の3タブ切替は機能的だが、初見で「どれを選べばいいか」がやや分かりづらい可能性
    • 出力パネル: lgブレークポイント以上でのみ表示。md幅では出力が隠れる設計は意図的か？

    3. Blocklyエディタ¶

    実装分析¶

    • Dynamic import で遅延読み込み（next/dynamic, SSR: false） — 正しい設計
    • コード表示エリア: minHeight: 80px, maxHeight: 140px, overflowY: auto — 適切な制約
    • コード変更時のフラッシュアニメーション: code-flash CSSクラスで視覚フィードバック
    • availableBlocks制御: クエストごとに使用可能ブロックを制限（良い設計）

    利用可能ブロック種別¶

    • print — 出力
    • text — テキスト
    • text_join — 文字列結合
    • math_number — 数値
    • math_arithmetic — 四則演算
    • variables — 変数

    MVP段階としては十分なブロック種類。段階的に増やす設計が見える。

    懸念点¶

    • BlocklyEditorコンポーネント自体のソースはChunk分離されており詳細未確認
    • ツールボックスのカテゴリ構成、ブロックのカスタムスタイル等はBlockly初期化コードに依存

    4. 実行・判定体験¶

    Python実行エンジン（Skulpt）¶

    • CDNから動的読み込み: skulpt.org/js/skulpt.min.js + skulpt-stdlib.js
    • 実行制限: execLimit: 5000（5秒） — 無限ループ対策として適切
    • 出力正規化: A() 関数で末尾空白除去、全角→半角変換、全角スペース→半角変換
    • これは秀逸: 子供が全角文字を入力しがちな問題を自動解決

    エラーハンドリング（15パターン）¶

    TimeLimitError → ⏰ くり返しが止まらない
IndentationError → 📏 スペースの数
SyntaxError(EOL) → 📝 クォーテーション閉じ忘れ
SyntaxError → 🔍 書き方の間違い
NameError(pritn) → 🤔 "print"の間違い？
NameError(prnt) → 🤔 "print"の間違い？
NameError → 🤔 名前が見つからない
TypeError(concatenate) → 🔀 文字と数字
TypeError → ⚠️ データの種類
ZeroDivisionError → 🚫 0で割る
IndexError → 📋 リスト範囲超え
ValueError → 🔢 値がおかしい
KeyError → 🔑 キーがない
AttributeError → ❓ 機能が使えない
RecursionError → 🔄 呼びすぎ

    評価: 非常に良い。 子供向けとして、エラーメッセージの質は競合他社と比べても高水準。emoji + 平易な日本語 + 具体的なアドバイスの3点セットが揃っている。

    判定ロジック¶

    • 正規化後の文字列完全一致 → シンプルで正しい
    • 星評価: ヒント未使用+1回目クリア=★3、ヒント未使用=★2、それ以外=★1

    5. ゲーム体験¶

    クエスト構成（8クエスト）¶

    # タイトル 難易度 XP コイン 学習内容
    1 はじめてのprint basic 30 20 print + text
    2 いろんな文字を表示しよう practice 30 20 複数print
    3 文字をつなげよう basic 40 25 text_join
    4 自己紹介を作ろう practice 40 25 text_join応用
    5 計算してみよう basic 40 25 四則演算
    6 いろんな計算 practice 40 25 かけ算
    7 変数を使おう basic 50 30 変数導入
    8 変数で計算 challenge 60 40 変数+演算

    設計として優れている点: - basic → practice の交互構成で「学ぶ→試す」のサイクルが自然 - XP/コインが段階的に増加しモチベーション維持 - 各クエストに3段階のヒントとNPC対話

    ワールド構成¶

    • ✅ スクラッチの森（実装済み・8クエスト）
    • 🔒 変換の洞窟（Lv.4で解放）
    • 🔒 Pythonの大地（Lv.6で解放）
    • 🔒 turtleの草原（Lv.8で解放）

    将来の拡張パスが明確で、ユーザーに「まだ先がある」期待感を持たせている。

    ゲーミフィケーション要素¶

    • XPとレベルシステム（100XP刻み推定）
    • コイン（現時点では使途不明 → 将来のショップ/カスタマイズ用？）
    • ★評価（1-3段階）
    • クリア演出（紙吹雪40個、スプリングアニメーション、カウントアップ）
    • 失敗時の励まし（試行回数に応じたメッセージ変化）

    6. パフォーマンス¶

    バンドルサイズ分析¶

    チャンク サイズ 内容
    メインページ 6KB ホーム画面コンポーネント
    クエストページ 42KB クエスト画面 + 全UI
    Framer Motion 117KB アニメーションライブラリ
    Blockly 127KB エディタ（動的読み込み）
    Next.js Runtime 225KB フレームワーク
    その他 ~150KB styled-jsx, React等

    合計: 約670KB（gzip前）

    評価¶

    • Blocklyの動的読み込みは正しい判断
    • Framer Motionの117KBはやや重いが、アニメーション品質とのトレードオフとしては許容範囲
    • Skulpt（Python実行エンジン）は外部CDNから読み込み — 初回実行時にラグの可能性あり

    最適化提案¶

    • Skulptをセルフホスト化してService Workerでキャッシュ
    • Framer Motion → CSS Animationsへの段階的移行（将来的に）

    7. バグ・不具合¶

    ソースコード上で確認された潜在的問題¶

    1. Skulpt CDN依存: skulpt.org がダウンした場合、Python実行が完全に機能停止する。エラーハンドリングはe.onerror=()=>e(!1)で存在するが、ユーザーへの通知が「Python実行エンジンが読み込まれていません」のみ
    2. リスク: 中（CDN障害時に全機能停止）

    3. 推奨: セルフホスト化またはフォールバック

    4. 全角→半角変換の範囲: [\uff01-\uff5e] で変換しているが、全角カッコ （） は範囲外。クエスト内容に全角カッコを使う場合に不一致が起こる可能性

    5. リスク: 低（現在のクエストでは問題なし）

    6. 次のクエストIDの計算: 1-${parseInt(l.id.split("-")[1])+1} — ワールド2以降のIDが 2-1 形式の場合、1- ハードコードで壊れる

    7. リスク: 中（ワールド拡張時に必ずバグになる）

    8. 推奨: クエストデータから次クエストを参照する設計に変更

    9. localStorage依存: ゲームの進捗がlocalStorageに保存されている模様。クリアすると進捗全消失

    10. リスク: 低（MVP段階では許容）

    11. 将来: クラウド同期の検討

    12. 出力パネルの表示条件: lg:flexで制御されているため、md幅（768-1024px）では出力パネルが非表示。タブレット横向きで出力が見えない可能性

    13. リスク: 中（タブレット利用者に影響）

    8. 子供目線での評価¶

    🟢 良い点（子供が喜ぶ要素）¶

    • ブロッくん（NPC）が常に励ましてくれる: 失敗時も「あきらめないで！」
    • 紙吹雪クリア演出: 40個のemoji紙吹雪は子供に刺さる
    • ヒント段階公開: 1回目で解けなくても、段階的にヒントが増える安心感
    • 🧩 ブロッくん: キャラクター設定が明確で親しみやすい
    • ミッション形式: 「RPGのクエスト」として学習をラップしている設計が秀逸
    • 全角→半角自動変換: 子供が全角で入力しても正しく判定される（ストレス軽減）

    🟡 改善したい点¶

    • コインの使い道が不明: 「コインもらったけど何に使うの？」が生まれる
    • マップに戻るボタンの視認性: text-sm text-slate-500 は子供には見つけにくい
    • ワールド選択の「🔒」: 解放条件は書かれているが、「あと何XPで解放？」が分かるとモチベーション維持に

    🔴 要注意¶

    • チュートリアルスキップの誘惑: 「スキップ」ボタンが目立ちすぎず良いが、一度スキップすると二度と見られない（localStorageにフラグ保存）
    • 失敗が連続した時: 5回以上失敗すると「ヒントを見て」だけ。動画やアニメーションでの解法デモがあるとさらに良い

    9. 改善提案（優先度付き）¶

    🔴 高優先度（リリース前に対応推奨）¶

    1. Skulptのセルフホスト化
    2. CDN障害リスクの排除
    3. 工数: 1-2時間

    4. public/ に配置して <script src="/skulpt.min.js"> に変更

    5. 次クエストID計算のハードコード修正

    6. ワールド拡張時のバグを事前防止
    7. 工数: 30分

    8. クエストデータの配列インデックスで次を取得する形に

    9. md幅での出力パネル表示

    10. タブレット横向きで出力が見えない問題
    11. 工数: 30分
    12. md:flex に変更するか、タブ切替をmd幅でも有効にする

    🟡 中優先度（初期リリース後に対応）¶

    1. コインの用途の提示
    2. 「ショップ（準備中）」のUIだけでも配置

    3. 工数: 1-2時間

    4. チュートリアル再表示機能

    5. 設定画面またはヘルプボタンからリプレイ可能に

    6. 工数: 1時間

    7. 進捗のエクスポート/インポート

    8. localStorage消失対策

    9. 工数: 2-3時間

    10. サウンドフィードバックの音量調整UI

    11. ソースにサウンド有効化の記述があるが、ON/OFF/音量のUI確認必要
    12. 工数: 1-2時間

    🟢 低優先度（将来的に検討）¶

    1. 解法デモアニメーション: 多数失敗時のフォロー
    2. アクセシビリティ: キーボードナビゲーション、スクリーンリーダー対応
    3. PWA対応: オフラインでも遊べるように
    4. 保護者向けダッシュボード: 学習進捗の可視化
    5. Framer Motion → CSS Animations移行: バンドルサイズ削減

    10. 総括¶

    第1回 B+ → 第2回 A- → 第3回 A¶

    Python Quest MVPは、第3回レビューで 教育系Webアプリとしての最低限のクオリティライン（MVP）を明確に超えた と判断する。

    特に評価する点: - 前回指摘の 100%反映率 — 開発チームのレスポンスの速さと正確さが光る - エラーメッセージの日本語化15パターン — 子供向け教育ツールとして、この品質は競合（Scratch, Progate, paiza等）と比較しても遜色ない - 全角→半角自動変換 — 地味だが、日本の子供向けツールとして極めて重要な配慮 - チュートリアル導入 — 初見ユーザーの離脱率を大幅に下げるはず - 段階的なヒントシステム — 教育設計として模範的

    A+に届かない理由: - Skulpt CDN依存（運用リスク） - ワールド拡張時の既知バグ要因（次クエストID） - md幅での出力パネル非表示 - コイン用途の未実装（ゲームデザイン上の穴）

    結論: 子供に触らせて実際のフィードバックを取るフェーズに進んでよい。 技術的な致命的問題はなく、UX上の重要な配慮も十分になされている。高優先度の3項目を修正すれば、限定公開（友人の子供等）でのユーザーテストを推奨する。

    レビュー実施環境: ソースコード静的解析（Next.js Turbopack バンドルJS分析）。ブラウザ実機操作は環境制約により未実施。Blocklyのドラッグ操作感、サウンドフィードバック、実際のアニメーション体感については次回レビュー時に確認予定。
