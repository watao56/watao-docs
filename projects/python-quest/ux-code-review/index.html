    Python Quest - UI/UX・コードレビュー¶

    シニアUI/UXエンジニアによる厳格レビュー URL: https://python-quest-three.vercel.app レビュー日: 2026-02-17 ソースコード: /home/node/clawd/python-quest/src/

    総合評価: B（MVPとしては合格、プロダクトリリースには不足）¶

    MVPとしての基本機能は揃っているが、UI品質・アクセシビリティ・コード設計に複数の深刻な問題がある。子供が一人で使うプロダクトとしては、もう1〜2スプリント分の改善が必要。

    1. UI品質¶

    良い点¶

    • ダークテーマの世界観が統一されており、ゲーム感がある
    • グラデーション・グロウエフェクトの使い方がRPG風でターゲットに合っている
    • 絵文字を効果的にアイコン代わりに使っており、追加アセット不要で視覚的に伝わる
    • Press Start 2P フォントのアクセント使いは適切
    • ClearModalの紙吹雪アニメーション・CountUpは達成感を演出できている
    • XPバーのシマーアニメーションは高品質

    問題点（深刻度付き）¶

    🔴 Critical¶

    1. コントラスト比がWCAG AA不適合（複数箇所）
    2. text-slate-500 (#64748b) on #0a0a1a → コントラスト比 約3.2:1（AA要件 4.5:1に不適合）
    3. text-[#4a4a6a] on #0a0a1a → 約2.0:1（完全に不適合）
    4. text-[#333]のロックアイコン → ほぼ見えない
    5. NPCダイアログの text-purple-200 は読みやすいが、text-slate-500 の説明文は子供には読みにくい

    6. 影響: 視力の弱い子供、明るい部屋でのモニター使用時に致命的

    7. フォントサイズの不統一・小ささ

    8. ワールドマップのスター表示 text-[8px] → 子供には完全に読めない
    9. XPバーの情報が text-sm (14px) で小さすぎる
    10. クエストノードのテキスト text-sm → タップターゲットは12x12だが表示テキストが小さい

    🟡 Major¶

    1. animate-pulseの使い方が不適切
    2. 利用可能クエストノードに animate-pulse を使用 → 常時点滅はアクセシビリティガイドライン違反（prefers-reduced-motion 未対応）

    3. てんかん誘発リスクは低いが、注意散漫の原因になる

    4. CTA「冒険をつづける」ボタンの常時スケールアニメーション

    5. scale: [1, 1.05, 1] が永続的に繰り返される → 落ち着きがなく、UIの品質を下げる

    6. 初回注目を引いた後は停止すべき

    7. フライアウト幅のハードコード

    8. max-width: 200px !important で強制制限 → ブロック名が切れる可能性がある
    9. !important 乱用（globals.cssに4箇所）

    🟢 Minor¶

    1. ロック済みワールドの opacity: 0.35

    2. 情報としては読ませたいが、opacity 0.35は低すぎる。0.5〜0.6が適切

    3. レスポンシブブレークポイントのギャップ

    4. md と lg でレイアウトが大きく変わる（2カラム → 3カラム）が、中間状態の考慮不足
    5. タブレット横向き（1024px付近）で出力パネルが突然現れる

    スコア: C+（コントラスト問題が深刻）¶

    2. UX品質¶

    良い点¶

    • ミッションイントロモーダルでクエスト開始前にNPCが説明 → 文脈設定が良い
    • チュートリアルのステップインジケーター（ドット表示）が分かりやすい
    • FailModalの段階的メッセージ（試行回数に応じた励まし）は教育的に優秀
    • diff表示で期待値と実際の出力を並べる → 何が間違っているか視覚的に分かる
    • エラーメッセージの日本語化が丁寧（15パターン対応）
    • ワールドマップ → クエスト → クリア → 次のクエストの導線が明確
    • 正解判定のnormalize処理（全角半角変換）が子供の入力ミスに寛容

    問題点（深刻度付き）¶

    🔴 Critical¶

    1. モバイルでのBlocklyエディタ操作性
    2. タブ切り替え式UIで、エディタと出力を同時に見られない
    3. ブロックを組み立てた後、出力タブに切り替えて確認、またエディタに戻る → 認知負荷が高い
    4. Blocklyのタッチ操作（ピンチズーム・ドラッグ）とページスクロールの競合未対応

    5. 小学4年生がスマホで使うケースを考えると致命的

    6. チュートリアルがクエスト1-1でしか表示されない

    7. localStorageベースで一度完了すると二度と表示されない
    8. リセット手段がUI上にない

    9. 新しいブロック種類（結合、計算、変数）が登場するクエストでの追加チュートリアルがない

    10. 「もう一度」の体験が不親切

    11. FailModal閉じた後、ブロックはそのまま → 何を直せばいいか分からない
    12. エラー箇所のハイライトやブロックへの視覚的フィードバックがない

    🟡 Major¶

    1. 戻るボタンの発見困難性
    2. 「← マップに戻る」がサイドバー最下部の text-slate-500 → 見つけにくい
    3. ブラウザバックに依存するユーザーが多いはず（子供は特に）

    4. ヘッダーに常時表示すべき

    5. クリア後の自動遷移がない

    6. ClearModal表示後、ユーザーが「次のクエストへ」を押さないと進めない

    7. 子供は達成感で興奮しているときに次のアクションを忘れがち

    8. コイン（coins）の使い道が不明

    9. コインを獲得するがUIに表示されない（XPバーにも、マップにもない）

    10. 報酬として表示されるが使えない → 期待を裏切る

    11. Skulpt CDN依存のリスク

    12. skulpt.org からの外部スクリプト読み込み → CDNダウン時にアプリ完全停止
    13. ローディング状態の表示がない（skulptReady=falseの間、実行ボタンがdisabledなだけ）

    14. 子供には「なぜ押せないの？」が分からない

    15. サイドバー折りたたみ時のアイコンのみ表示

    16. 📋🎯💡 のアイコンだけでは何ができるか分からない
    17. tooltip もない

    🟢 Minor¶

    1. ヒントボタンがFailModal内にしかない
    2. 失敗する前にヒントを見たい子供がいるはず

    3. サイドバーにヒントボタンを常時表示すべき

    4. クエスト選択時のステータス表示不足

      • クリア済みクエストを再プレイできるが、そのことが伝わらない

    スコア: C+（モバイル体験とチュートリアル不足が深刻）¶

    3. コード品質¶

    良い点¶

    • Zustand + persist の選択は適切。教育アプリの進捗保存にぴったり
    • partialize でストアの永続化対象を絞っている
    • SSRハイドレーション対策（mounted state）を意識している
    • normalizeOutput で全角半角を吸収 → 実用的
    • TypeScriptの型定義が概ね適切（Quest, QuestProgress, GameState）
    • dynamic import でBlocklyをSSR回避
    • エラーメッセージの翻訳パターンが拡張しやすい設計

    問題点（深刻度付き）¶

    🔴 Critical¶

    1. QuestPageの巨大コンポーネント（約250行）
    2. 状態が11個（useState x 11）→ 責務過多
    3. ミッションイントロ、チュートリアル、エディタ、出力、サイドバー、モーダル2種が1コンポーネントに
    4. テスト不可能、メンテナンス困難

    5. 分割案: QuestSidebar, QuestEditor, QuestModals, MissionIntro に分離すべき

    6. handleRun 内でのストア直接呼び出し（レンダリング中の状態読み取り）

    7. getQuestProgress をイベントハンドラ内で呼んでいるが、クロージャの問題でstale stateになる可能性

    8. clearQuest の直後に getQuestProgress → 更新が反映されない可能性

    9. Skulptのwindow.Sk直接参照

    10. グローバル変数汚染
    11. TypeScript的に declare global で逃げているが、型安全性ゼロ

    12. Skulptの読み込みエラー時のリカバリがない

    13. pythonRunner.tsにerrorMessages.tsの内容が重複

    14. translateError が errorMessages.ts に定義されているが、pythonRunner.ts にも同じパターン配列がコピペされている → 二重管理

    🟡 Major¶

    1. BlocklyEditorのonCodeChangeコールバック
    2. 親から渡される handleCodeChange は useCallback だが、依存配列が空 → 問題ないが、将来的にバグの温床
    3. BlocklyのchangeListenerが高頻度で発火 → デバウンスなし

    4. 毎回 generatePython が走る → パフォーマンス懸念

    5. @ts-expect-error の使用

    6. flyoutAutoClose に対して型エラーを抑制 → Blocklyの型定義更新で壊れるリスク

    7. (flyout as any), (Blockly as any) が複数箇所 → 型安全性の放棄

    8. CSSの !important 乱用

    9. globals.css内に !important が7箇所
    10. Blocklyのスタイル上書きに必要だが、コメントで理由が書かれていない

    11. より良い方法: Blocklyのテーマ設定で対応可能な箇所がある

    12. アクセシビリティ属性の完全欠如

    13. aria-label, aria-live, role が一切ない
    14. クエストノードボタンにラベルなし → スクリーンリーダーでは「ボタン 1」としか読まれない
    15. モーダルに role="dialog", aria-modal="true" なし
    16. キーボード操作: Escでモーダルを閉じられない

    17. フォーカストラップなし

    18. useEffect の依存配列問題

    19. BlocklyEditor: availableBlocks が配列なので、親が再レンダリングするたびに新しい参照 → Blockly再初期化のリスク（実際にはrefチェックで防がれているが偶然）

    🟢 Minor¶

    1. コンポーネントファイルの整理不足

      • components/ 直下にフラットに配置 → 機能別ディレクトリ（components/quest/, components/modals/）に分けるべき

    2. マジックナンバー

      • setTimeout(() => setShowClear(true), 2500) の2500msが定数化されていない
      • XPバーの Math.min((xp / 100) * 100, 100) → 100がレベルテーブルと無関係のハードコード

    3. Press Start 2P フォントのGoogle Fonts読み込み

      • <head> 直接 → Next.jsの next/font を使うべき（パフォーマンス最適化）

    4. テストの不在

      • テストファイルが1つもない
      • normalizeOutput, translateError, ストアのロジックは単体テスト必須

    スコア: C（巨大コンポーネント・アクセシビリティ欠如・テストなし）¶

    4. 子供向けプロダクトとしての評価¶

    良い点¶

    • RPGメタファー（クエスト、ワールド、レベル、XP）は小学生に馴染みやすい
    • ブロッくんのキャラクター性があり、対話形式のガイドは効果的
    • ヒントが段階的に表示される仕組みは教育的に正しい
    • 失敗時の励ましメッセージが試行回数に応じて変化 → 挫折防止
    • エラーメッセージの日本語化が丁寧で、子供でも理解できる表現
    • クエスト設計がprint → 文字結合 → 計算 → 変数と段階的

    問題点¶

    🔴 致命的¶

    1. 「何をすればいいか分からない」瞬間が多すぎる
    2. チュートリアルが初回のみ。クエスト1-3で「結合ブロック」が初登場するが説明なし
    3. NPCのダイアログだけでは、Blocklyの操作方法（ドラッグ→接続→値入力）を理解できない

    4. 対策: 各クエストの新概念にインタラクティブチュートリアルが必要

    5. ダークテーマ固定

    6. 子供向けアプリでダークテーマ固定はリスク
    7. 明るい教室、保護者と一緒に見る場面 → 暗い画面は不自然

    8. ライトテーマオプションまたは明るめダークが望ましい

    9. 保護者機能の不在

    10. 進捗確認、使用時間、リセット機能がない
    11. localStorage依存でデバイス間同期なし

    🟡 重要¶

    1. 報酬システムの未完成
    2. コインの使い道がない → 集める動機がない
    3. スター3つの条件が不透明（ヒント0回＆1回で正解）→ 子供には分からない

    4. レベルアップの演出がない（静かにレベルが上がる）

    5. ゲームオーバーがない（良い面もある）

    6. 無限リトライ可能は教育的に良いが、チャレンジ感が薄い

    7. 時間制限や「残りHP」のような緊張感の仕組みがあると良い

    8. クエスト数が少なすぎる（8問）

    9. ワールド1のみで完結 → 30分〜1時間で終わる
    10. 終わった後の「次にやること」がない

    スコア: B-（基本的な教育設計は良いが、自立学習には不十分）¶

    5. 改善提案（優先度・工数付き）¶

    P0（リリース前必須）¶

    # 改善内容 工数 理由

    4 Skulptローカルバンドル or フォールバック 3h CDN障害時のサービス停止防止

    8 各クエスト新概念時のミニチュートリアル 8h 子供の自立学習に必須
    9 ヒントボタンのサイドバー常時表示 1h 失敗前にヒントを見たい
    10 戻るボタンのヘッダー移動 0.5h ナビゲーション改善

    P2（中期改善）¶

    13 レベルアップ演出 3h ゲーム体験の向上
    14 next/font への移行 1h パフォーマンス
    15 テスト追加（normalizeOutput, store, translateError） 4h 品質保証
    16 BlocklyのchangeListenerデバウンス 2h パフォーマンス
    17 保護者ダッシュボード 16h 進捗確認、利用管理
    18 クエスト追加（ワールド2以降） 20h+ コンテンツ拡充

    6. 総括¶

    MVPとしての評価¶

    Python QuestはMVPとしての最低限の機能は達成している。ブロックプログラミング→Python変換→実行→正解判定の基本ループが動作し、8つのクエストで段階的学習ができる。RPG風のUIとキャラクター（ブロッくん）による対話的ガイドは、子供向けプロダクトの方向性として正しい。

    プロダクトリリースとしての評価¶

    現状ではリリース不可。以下が主な理由:

    1. アクセシビリティの完全欠如 — 教育プロダクトとして、WCAG AA準拠は最低ライン。aria属性ゼロ、コントラスト不適合は公開NGレベル
    2. モバイル体験の貧弱さ — 子供のメインデバイスがスマホ/タブレットであることを考えると、タブ切り替え式UIは致命的
    3. 自立学習の壁 — チュートリアルが初回のみで、新概念導入時のガイダンスがない。小学4年生が一人で使うには不十分
    4. コード品質 — 250行の巨大コンポーネント、テストゼロ、型安全性の放棄箇所が多く、チーム開発やメンテナンスに耐えない

    ポテンシャル¶

    設計思想は良い。RPGメタファー、段階的ヒント、子供向けエラーメッセージ翻訳、全角半角正規化など、ユーザーへの思いやりが感じられる設計判断が随所にある。P0改善（推定10h）を入れればβリリース可能、P1改善（推定28h）を入れれば正式リリース可能なレベル。
