    👁️ PageDiff — Webページ変更検知SaaS¶

    1. 概要・解決する課題¶

    なぜ金を払うか（1行）: 競合の価格改定・規約変更・在庫復活を見逃さず、ビジネス機会の損失を防ぐ。

    課題の深刻度¶

    • 競合が値下げしたのに気づかず顧客を奪われた
    • 利用中サービスのToS変更で不利な条件を知らずに受け入れていた
    • 狙っていた限定商品・ドメイン・物件の掲載を見逃した
    • 政府の補助金ページ更新を見逃して申請期限切れ
    • 手動チェックは非現実的（毎日10ページ確認？）

    なぜ「ないと困る」か¶

    ビジネスにおいて「知らなかった」は直接的な損失。月$5で情報格差を解消。

    2. ターゲットユーザー¶

    プライマリペルソナ¶

    高橋健太（35歳）- EC事業者 - Amazon/楽天で商品を販売 - 競合3社の価格ページを毎日手動チェックしている（1日30分） - 競合の値下げに1日遅れで気づき、売上が20%減った経験あり - 「自動で教えてくれるなら月$10でも払う」

    セカンダリペルソナ¶

    伊藤裕子（40歳）- 法務担当 - 利用中のSaaS 5社のToS/プライバシーポリシーを監視する義務がある - 現状: 四半期に1回手動チェック → 変更見逃しリスク - コンプライアンス上、変更検知は「あったら便利」ではなく「義務」

    3. 料金プラン¶

    プラン 月額 内容
    Free $0 3ページ、日次チェック、メール通知
    Pro $5/月 30ページ、1時間ごとチェック、Slack通知、差分ハイライト、CSSセレクタ指定
    Business $15/月 100ページ、15分ごとチェック、API、Webhook、スクリーンショット比較

    4. ユーザーフロー¶

    1. メールでサインアップ（30秒）
2. 監視したいURLを入力
3. オプション: CSSセレクタで監視範囲を絞る（例: .price-tag）
4. 初回スナップショット取得
5. 以降、定期チェックで変更検知
   - 変更あり → メール/Slack通知
   - 差分表示（追加: 緑、削除: 赤）
6. ダッシュボードで全ページの状態一覧

    6. コンポーネント詳細¶

    6.1 ページフェッチャー (Lambda)¶

    • Node.js fetch でHTMLを取得
    • CSSセレクタ指定時: cheerioでDOM抽出
    • JavaScript描画ページ: 非対応（MVP外。Phase3でPuppeteer対応検討）
    • User-Agent: 通常ブラウザを模倣
    • タイムアウト: 10秒

    6.2 差分エンジン (Lambda)¶

    • テキスト差分: diff ライブラリ（word-level diff）
    • ノイズ除去: タイムスタンプ、セッションID等の動的要素を自動フィルタ
    • 変更率閾値: 0.1%未満の変更は無視（広告等のノイズ対策）
    • 結果をDynamoDBに保存、前回のスナップショットをS3に保存

    6.3 通知エンジン¶

    • 変更検知時のみ通知（差分なし→何もしない）
    • メール: 差分ハイライト付きHTML
    • Slack: 要約 + ダッシュボードリンク

    7. データベース設計¶

    DynamoDB¶

    Users テーブル 

    PK: USER#{user_id}
SK: PROFILE
Attributes: email, plan, slack_webhook_url, stripe_customer_id, created_at

    Pages テーブル 

    PK: USER#{user_id}
SK: PAGE#{page_id}
Attributes:
  - url: string
  - css_selector: string (optional)
  - check_interval: "daily" | "hourly" | "15min"
  - last_checked: ISO8601
  - last_changed: ISO8601
  - status: "active" | "paused" | "error"
  - error_count: number

    Changes テーブル 

    PK: PAGE#{page_id}
SK: CHANGE#{timestamp}
Attributes:
  - diff_summary: string (変更行数、追加/削除)
  - diff_s3_key: string (詳細差分のS3パス)
  - snapshot_s3_key: string

TTL: 90日（Pro）/ 30日（Free）

    S3¶

    • snapshots/{page_id}/{timestamp}.html - 各チェック時のHTML
    • diffs/{page_id}/{timestamp}.json - 差分データ

    AIコスト: $0（テキスト差分のみ、AI不使用）¶

    9. MVPスコープ¶

    Phase 1: コアMVP（2週間）¶

    • メール認証 + ダッシュボード
    • URL登録 + 初回スナップショット
    • 定期フェッチ + テキスト差分
    • メール通知（変更時）
    • 差分ビューア
    • 工数: 10日

    Phase 2: 有料機能（1週間）¶

    • Stripe決済
    • CSSセレクタ指定
    • Slack通知
    • チェック頻度設定
    • 工数: 5日

    Phase 3: 拡張（2週間）¶

    • スクリーンショット比較（Puppeteer）
    • API / Webhook
    • JavaScript描画ページ対応
    • 工数: 10日

    10. 周知・マーケティング計画¶

    Week 1-2: ターゲット直接アプローチ¶

    EC事業者向け: - Yahoo!ショッピング・楽天のセラーフォーラム: 「競合の価格変動を自動監視するツール使ってる人いますか？」から自然にサービス紹介 - Twitter/X EC関連アカウント: 「競合の値下げに1日遅れで気づくのはもう終わり。30秒でセットアップ、価格変動をSlackに即通知 → [URL]」 - タイミング: 火・木 10:00 JST

    法務・コンプライアンス向け: - note記事: 「SaaSの利用規約変更を見逃すリスクと対策 — 自動監視のすすめ」 - Twitter: 「利用中のSaaSがこっそりToS変更してて困った経験ありませんか？自動監視サービス作りました」

    Week 3-4: 開発者向け¶

    • Zenn: 「Webページの変更検知を自動化する方法 — DIY vs SaaS比較」
    • Product Hunt: ローンチ
    • r/webdev, r/entrepreneur: 英語版投稿

    継続施策¶

    • 「このページの変更を監視する」ブックマークレット提供 → バイラル

    12. リスクと対策¶

    リスク 深刻度 対策
    動的ページ（SPA）の対応 High MVP: SSRページのみ対応と明記。Phase3でPuppeteer Lambda Layer追加
    サイト側のBot対策（CAPTCHA、IP制限） Medium User-Agentローテーション、429時のバックオフ、対応不可サイトはユーザーに通知
    ノイズ（広告、タイムスタンプ等の誤検知） High CSSセレクタで範囲限定、変更率閾値、ユーザーが無視パターンを設定可能
    S3コスト増大（大量スナップショット） Medium TTLで古いデータ削除、圧縮保存、Free30日/Pro90日
    Lambda同時実行数上限 Low SQSバッファリング、reserved concurrency

    13. 競合分析・差別化¶

    機能 PageDiff Visualping ($10/月〜) ChangeTower ($5/月〜) Distill.io (Free+$15/月)
    最低有料プラン $5/月 $10/月 $5/月 $15/月
    無料枠 3ページ 5ページ（限定的） 5ページ 25ページ（5分間隔なし）
    CSSセレクタ ✅ Pro ✅ ✅ ✅
    Slack通知 ✅ Pro ✅ (高額プラン) ❌ ✅
    API ✅ Business ✅ (Enterprise) ❌ ✅
    日本語UI ✅ ❌ ❌ ❌
    チェック間隔最小 15分 5分 1時間 10秒（ブラウザ）

    なぜ勝てるか¶

    1. 日本語UI: 競合は全て英語。日本市場でのUXアドバンテージ
    2. 価格: Visualpingの半額で主要機能カバー
    3. 開発者フレンドリー: API+Webhook+Slack統合がProから使える
    4. EC事業者特化のマーケティング: 競合は汎用ツール。EC価格監視に特化した訴求
