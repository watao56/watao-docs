    🛎️ FormShield — お問い合わせフォーム死活監視¶

    概要¶

    Webサイトのお問い合わせフォームが「壊れていても気づかない」問題を解決する。フォームが壊れると問い合わせがゼロになり、機会損失が発生するが、オーナーは「問い合わせが少ない時期かな」と放置しがち。FormShieldは定期的にフォーム送信をシミュレートし、送信失敗・メール未着を検知して即座にアラートを送る。

    ターゲットユーザー¶

    • 中小企業のWeb担当者: フォーム経由の問い合わせが売上に直結
    • フリーランスのWebデザイナー: クライアントサイトのフォーム管理
    • ECサイトオーナー: カスタマーサポートフォームの監視
    • 不動産・クリニック等: 予約フォームが生命線の業種

    料金プラン¶

    プラン 月額 内容
    Free $0 フォーム1件、1日1回チェック
    Pro $5/月 フォーム10件、1時間ごとチェック、Slack/メール通知
    Business $12/月 フォーム50件、15分ごとチェック、Webhook対応

    ユーザーフロー¶

    1. メールアドレスでサインアップ（10秒）
    2. 監視したいフォームのURLを入力
    3. FormShieldがフォームを自動検出し、テスト送信先メールを設定
    4. 定期的にヘッドレスブラウザでフォーム送信をシミュレート
    5. 送信成功→メール到着を確認（専用受信アドレスで検証）
    6. 失敗時→即座にメール/Slack/LINE通知
    7. ダッシュボードで稼働状況を確認
    8. Freeプランの制限に当たったら有料プランへ

    アーキテクチャ¶

    [ユーザー] → [Next.js on Vercel (フロント/API)]
                    ↓
            [Supabase (認証/DB)]
                    ↓
[EventBridge Scheduler] → [Lambda (Puppeteer)]
                    ↓
            [フォーム送信シミュレート]
                    ↓
        [SES受信 (専用ドメイン)] → 到着確認
                    ↓
            [未着検知] → [SNS → メール/Slack通知]

    DB設計¶

    usersテーブル¶

    カラム 型 説明
    id uuid PK
    email varchar ログインメール
    plan enum free/pro/business
    created_at timestamp 登録日時

    formsテーブル¶

    カラム 型 説明
    id uuid PK
    user_id uuid FK
    url varchar フォームURL
    form_selector varchar フォーム要素のセレクタ
    test_email varchar テスト送信先メール
    check_interval int チェック間隔（分）
    status enum active/paused/error

    check_logsテーブル¶

    カラム 型 説明
    id uuid PK
    form_id uuid FK
    checked_at timestamp チェック日時
    submit_success boolean 送信成功したか
    email_received boolean メール到着したか
    error_message text エラー詳細

    コスト見積もり¶

    項目 月額
    Vercel (Hobby) $0
    Supabase (Free) $0
    Lambda (Puppeteer) ~$1（1000回実行/月）
    SES (受信) ~$0.10
    EventBridge ~$0.01
    合計 ~$1.11

    AIコスト: なし（AI不使用）

    MVPスコープ¶

    • メールアドレス認証でサインアップ
    • フォームURL入力→自動フォーム検出（Puppeteer）
    • 1日1回のフォーム送信テスト
    • メール到着確認（SES受信ルール）
    • 失敗時のメール通知
    • シンプルなダッシュボード（最新10件のチェック結果）

    マーケティング計画¶

    • SEO: 「お問い合わせフォーム 動かない」「フォーム 壊れた 気づかない」等のキーワード記事
    • Twitter/X: 「フォームが壊れてて3ヶ月気づかなかった」系の共感ツイート
    • Web制作コミュニティ: フリーランスのWebデザイナーに「クライアント管理ツール」として訴求
    • Product Hunt: ローンチ
    • ブログ: 「フォーム障害で逃した売上」のケーススタディ記事

    技術スタック¶

    • フロント: Next.js (App Router) + Tailwind CSS
    • ホスティング: Vercel (Hobby)
    • 認証/DB: Supabase
    • フォームテスト: AWS Lambda + Puppeteer (chromium layer)
    • スケジューラ: Amazon EventBridge Scheduler
    • メール受信: Amazon SES (Receiving)
    • 通知: Amazon SNS → メール / Slack Webhook

    リスクと対策¶

    リスク 対策
    フォーム構造が多様でパース困難 主要フォームビルダー(Contact Form 7, Googleフォーム等)に対応。カスタムセレクタ設定も可能
    スパム判定されるリスク テスト用の識別子を付与。ユーザーにホワイトリスト設定を案内
    Puppeteerのメンテコスト Lambda Layerで管理。定期的にchromiumバージョン更新
    reCAPTCHA付きフォーム reCAPTCHAテストキー設定をユーザーに案内。対応不可の場合はHTTPステータスのみ監視

    競合分析¶

    サービス 違い
    UptimeRobot URL死活監視のみ。フォーム送信テストはしない
    Freshping 同上。HTTPレスポンス監視
    手動テスト 忘れる。月1回すらやらない

    差別化: 「フォームが動いているか」ではなく「フォームから送ったメールが届くか」まで検証する唯一のサービス。

    $20達成シナリオ¶

    • Proプラン($5) × 4人 = $20/月
    • フリーランスWebデザイナーが3-5クライアントのフォームを管理するユースケース
    • Free→Proの転換率15%想定で、Free 27人 → Pro 4人
    • SEO記事3本 + Twitter運用で月30サインアップ → 3ヶ月で達成
