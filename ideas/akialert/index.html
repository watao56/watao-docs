    🚨 AkiAlert - 人気施設キャンセル待ち通知サービス¶

    概要¶

    人気飲食店・美容院・クリニック等のキャンセル待ち自動監視＋即座通知サービス。手動チェック不要で、空きが出たら10秒以内にLINE/SMS/メール/Slackで即通知。忙しい現代人の「予約が取れない問題」を完全解決。

    ターゲット¶

    プライマリ¶

    • 激務会社員（25-40歳）: 人気レストラン・美容院の予約確保
    • 子育て世代（30-45歳）: 小児科・皮膚科等の予約困難クリニック
    • 美容意識高い層（20-35歳）: 話題のエステ・マッサージサロン

    セカンダリ¶

    • グルメ愛好家・デート予定のカップル
    • 健康管理意識高いビジネスパーソン
    • インフルエンサー・SNS発信者（話題の店舗確保）

    ペイン¶

    • 手動チェックの限界: 1日何度も予約サイト確認する疲労
    • タイミング逸失: 空きが出ても数分で埋まる高競争
    • 複数サイト監視: ホットペッパー、一休、Yelp等の分散チェック負荷
    • 機会損失ストレス: 「あと5分早ければ取れたのに」の後悔

    解決価値¶

    • 時間節約: 1日3回×5分の手動チェック → 0分（月4.5時間創出）
    • 確実性向上: 空きが出たら即時通知、予約確率3-5倍
    • ストレス軽減: 常時監視による安心感

    料金（段階制）¶

    • フリー: 月5通知まで無料（トライアル重視）
    • ライト: 月￥480（月20通知、24時間監視）
    • スタンダード: 月￥980（月60通知、複数施設監視、優先通知）
    • プレミアム: 月￥1,980（無制限、SMS通知、API連携）

    価格設定根拠¶

    • 美容院1回￥5,000の10%→￥500が適正価格感
    • 高級レストラン1回￥10,000の5%→￥500
    • 「予約取れない」機会損失回避の価値：￥1,000-2,000

    ユーザーフロー¶

    1. 施設登録: 希望の店舗・日時・人数を指定（30秒）
    2. 監視開始: 10分間隔で自動チェック開始
    3. 空き発見: 予約可能になった瞬間を検知
    4. 即時通知: 10秒以内にLINE/SMS/メール/Slack通知
    5. ワンクリック予約: 通知から直接予約サイトへ誘導
    6. 成功報酬: 予約完了時のみ通知回数消費

    アーキテクチャ¶

    フロントエンド¶

    • Web App: Next.js + TypeScript + Tailwind CSS
    • PWA: プッシュ通知対応、スマホアプリ風UX
    • LINE Bot: LINE公式アカウント連携

    バックエンド¶

    • API: Node.js + Fastify + TypeScript
    • DB: Supabase PostgreSQL（ユーザー、監視設定）
    • Scraping: Playwright + Proxy Rotation
    • Queue: Upstash Redis（監視ジョブスケジューリング）
    • 通知: LINE Messaging API, Twilio SMS, SendGrid

    インフラ（段階的）¶

    Phase 0（0-10ユーザー）¶

    • Vercel Hobby: ￥0/月（フロントエンド）
    • Railway Hobby: ￥0/月（バックエンド・スクレイピング）
    • Supabase Free: ￥0/月（DB）
    • Upstash Redis Free: ￥0/月（Job Queue）
    • 合計: ￥0/月（完全無料運用）

    Phase 1（10-100ユーザー）¶

    • Railway Pro: ￥1,500/月
    • Supabase Pro: ￥3,000/月（大量DB書き込み対応）
    • Proxy Service: ￥2,000/月（IP規制回避）
    • 合計: ￥6,500/月

    技術スタック¶

    • Frontend: Next.js 14, TypeScript, Tailwind CSS, PWA
    • Backend: Node.js, Fastify, Prisma ORM
    • Scraping: Playwright, Puppeteer-extra-plugin-stealth
    • Database: PostgreSQL
    • Queue: Redis + Bull
    • 通知: LINE API, Twilio, SendGrid, Slack Webhooks
    • Deployment: Vercel + Railway
    • Proxy: Proxy Mesh, Bright Data

    MVPスコープ（3週間）¶

    必須機能¶

    • ユーザー登録・認証（Google/LINE OAuth）
    • 施設監視登録（URL・日時・人数指定）
    • ホットペッパーグルメ単一対応スクレイピング
    • LINE通知（LINE Bot）
    • 基本ダッシュボード（監視状況確認）
    • 決済（Stripe、ライトプラン以上）

    Phase 1機能（MVP）¶

    • 1サイト監視（ホットペッパーグルメ）
    • LINE通知のみ
    • 手動施設登録

    Phase 2機能（差別化）¶

    • 多サイト対応: 一休、ぐるなび、Yelp追加
    • AI施設認識: URL貼り付けで自動施設情報抽出
    • SMS緊急通知: 重要な予約はSMS併用
    • 予約成功率分析: 通知→実予約の成功率レポート

    コスト見積もり¶

    変動コスト（主要）¶

    • Proxy料金: 月10万リクエスト→￥2,000
    • SMS通知: 1通￥10→プレミアムユーザーのみ
    • スクレイピング: 1監視対象あたり月￥5-10

- ライト￥480 × 60人 = ￥28,800
- スタンダード￥980 × 30人 = ￥29,400  
- プレミアム￥1,980 × 10人 = ￥19,800
合計: ￥78,000/月

固定費: ￥6,500/月
変動費: ￥15,000/月（平均月150監視）
純利益: ￥56,500/月（72%利益率）

    マーケ計画¶

    チャネル戦略¶

    1. SNS: 「予約取れた！」成功体験投稿促進
    2. 口コミサイト: 美容院・レストランレビューサイトで言及
    3. インフルエンサー: グルメ・美容系インフルエンサーお試し利用
    4. SEO: 「[店名] 予約 取れない」等のロングテール

    バイラル仕掛け¶

    • 紹介制度: 成功紹介で1ヶ月無料
    • 成功報告機能: 「AkiAlertで取れました！」SNSシェア
    • 限定店舗情報: プレミアム会員限定の「今狙い目の店」情報

    競合分析¶

    既存サービス¶

    1. Resy, OpenTable: 海外主要、国内対応限定
    2. ホットペッパー通知: 特定店舗のみ、タイミング遅い
    3. 予約アラートbot（個人開発）: 機能限定、単発サイト

    競合優位性¶

    • 網羅性: 複数予約サイト横断監視
    • 速度: 10秒以内即時通知（競合は数分～数時間遅延）
    • 精度: AI施設認識で設定ミス防止
    • 利便性: LINE1つで完結、アプリインストール不要

    リスク & 対策¶

    技術リスク¶

    1. Anti-bot対策: 予約サイトのスクレイピング規制
    2. 対策: Proxy Rotation, User-Agent偽装, 人間的アクセスパターン
    3. IP BAN: 大量アクセスでのアクセス制限
    4. 対策: 分散Proxy、適切な間隔調整

    法的リスク¶

    1. 利用規約違反: 各サイトのスクレイピング禁止条項
    2. 対策: robots.txt準拠、過度でない頻度、公開情報のみ
    3. 著作権: サイトデザインの模倣
    4. 対策: データのみ抽出、UI模倣なし

    ビジネスリスク¶

    1. サイト仕様変更: スクレイピング対象サイトの構造変更
    2. 対策: 複数サイト対応、自動復旧機能
    3. 利用規模制限: 大規模時のサーバー負荷
    4. 対策: 段階的インフラ強化、効率的スクレイピング
