    📋 PermitPing — 事業許認可更新期限リマインダー¶

    概要¶

    飲食店営業許可、建設業許可、宅建業免許、古物商許可、酒類販売免許、旅館業許可など、事業運営に必要な許認可の更新期限を管理し、申請準備開始のタイミングでアラートを送るサービス。許認可の期限切れは即座に営業停止となり、売上ゼロ＋罰金（50-300万円）のダブルパンチ。更新手続きには1-3ヶ月の準備期間が必要だが、多くの事業者がギリギリまで気づかない。

    ターゲット¶

    • メイン: 飲食店オーナー（営業許可は全飲食店に必須、約84万店舗）
    • サブ: 建設業、不動産業、リサイクルショップ、民泊事業者
    • 拡張: 行政書士（顧客の許認可を管理する業務ツール）
    • 非技術者向け: スマホから3タップで登録完了を目指す

    料金¶

    プラン 月額 内容
    Free $0 3件まで、メール通知のみ、90日前アラート
    Pro $3/月 20件、LINE/Slack通知、カスタムアラート（180日前、90日前、30日前、7日前）、申請チェックリスト
    Business $8/月 無制限、チーム共有、CSV管理、行政書士向けクライアント管理

    ユーザーフロー¶

    1. 登録: メールまたはLINEログイン
    2. 許認可追加: 種別をプルダウン選択（プリセット50+）→ 取得日・有効期限を入力
    3. 自動計算: 更新申請の推奨開始日を自動算出（種別ごとに必要準備期間をプリセット）
    4. 通知設定: 通知タイミングと通知先を設定
    5. アラート受信: 「建設業許可の更新まであと90日。申請書類の準備を開始してください」
    6. チェックリスト: 更新に必要な書類一覧（種別ごとにプリセット）
    7. 完了記録: 更新完了→次回の期限を自動更新

    アーキテクチャ¶

    [ユーザー] → [Next.js SPA] → [API Gateway]
                                    ↓
                              [Lambda Functions]
                                    ↓
                              [DynamoDB]
                                    ↓
                          [EventBridge: 毎日6:00 AM]
                                    ↓
                          [Lambda: 期限チェッカー]
                                    ↓
                    判定: 今日 = 通知日?
                          ↓ Yes
                    [SES / LINE Notify]

    コンポーネント¶

    • Frontend: Next.js（Vercel無料枠）
    • API: AWS Lambda + API Gateway
    • DB: DynamoDB
    • スケジューラ: EventBridge（毎日1回）
    • 通知: SES + LINE Notify + Slack Webhook
    • 認証: NextAuth.js（メール + LINE Login）

    DB設計¶

    Users テーブル¶

    フィールド 型 説明
    userId (PK) String UUID
    email String メール
    plan String free/pro/business
    lineToken String LINE Notify トークン
    createdAt Number 登録日

    Permits テーブル¶

    フィールド 型 説明
    userId (PK) String ユーザーID
    permitId (SK) String 許認可ID
    type String 種別（飲食店営業許可、建設業許可等）
    name String 表示名（自由記述）
    issuedAt String 取得日
    expiresAt String 有効期限
    renewalPeriod Number 更新周期（年）
    prepDays Number 必要準備期間（日）
    alertDays List 通知日（期限前X日）
    status String active/expiring/expired/renewed

    PermitTypes テーブル（プリセットマスタ）¶

    フィールド 型 説明
    typeId (PK) String 種別ID
    name String 種別名
    renewalYears Number 更新周期（年）
    prepDays Number 推奨準備期間（日）
    requiredDocs List 必要書類リスト
    penalty String 期限切れ時の罰則
    authority String 管轄官庁

    AlertHistory テーブル¶

    フィールド 型 説明
    userId (PK) String ユーザーID
    alertId (SK) String アラートID
    permitId String 対象許認可
    sentAt Number 送信日時
    channel String 通知チャネル

    MVPスコープ¶

    Phase 1（10日）¶

    • ユーザー登録（メール）
    • 許認可登録（手動入力＋プリセット20種）
    • 期限チェックバッチ（EventBridge毎日実行）
    • メール通知（90日前、30日前、7日前）
    • ダッシュボード（期限順一覧、ステータス表示）

    Phase 2（+5日）¶

    • LINE Notify連携
    • 更新チェックリスト（種別ごと）
    • Stripe決済
    • LINE Login対応

    Phase 3（+1週間）¶

    • 行政書士向けクライアント管理
    • CSV一括インポート
    • 更新完了→次回期限自動設定
    • プッシュ通知（PWA）

    マーケ計画¶

    初期（1-3ヶ月目）¶

    • SEO: 「飲食店 営業許可 更新忘れ」「建設業許可 更新期限」「許認可 期限管理」
    • 飲食店コミュニティ: 飲食店.COM、食べログ事業者フォーラム
    • 行政書士向け: 行政書士向けセミナー/ウェビナーで紹介
    • Googleビジネスプロフィール: 地域密着の検索対策

    中期（3-6ヶ月目）¶

    • 行政書士パートナーシップ: 顧客への導入推薦（紹介料）
    • 商工会議所: セミナー登壇、チラシ配布
    • 口コミ: 「営業許可の更新忘れで1週間営業停止した」体験談記事
    • 保険会社連携: 事業保険とセットで提案

    リスク¶

    リスク 影響 対策
    ユーザーが期限を間違えて入力 誤アラート/見逃し 許認可証の写真OCRで期限自動読取（Phase 3）
    CertRemindとの差別化認知 混乱 「事業許可専用」を明確に訴求。LP/メッセージで差別化
    許認可制度の変更 マスタデータ更新 官報/告示のRSSで変更を検知。四半期レビュー
    カレンダーアプリで代替 WTP低下 準備期間管理+チェックリストが差別化。単なるリマインドではない

    競合分析¶

    競合 特徴 PermitPingの優位性
    Googleカレンダー 汎用リマインダー 準備期間の逆算、必要書類チェックリストがない
    Excel管理 自由度高い 通知機能なし、テンプレートなし
    行政書士に丸投げ 確実 1件5-15万円。小規模事業者には高い
    CertRemind（自社） 個人資格向け 事業許認可は更新手続きが複雑。必要書類・管轄官庁情報が必要

    $20達成シナリオ¶

    シナリオ Pro ($3) Business ($8) MRR
    最速 4人 1人 $20
    現実的（3ヶ月目） 5人 2人 $31
    保守的（6ヶ月目） 8人 2人 $40

    達成根拠¶

    • 飲食店84万店舗 × 1%の認知 = 8,400人のリーチ
    • 営業停止リスク回避に$3/月は「保険として当然」の価格
    • 行政書士1人が採用すれば、顧客10-50社に波及
    • 許認可の更新は「忘れたら終わり」の恐怖が強力な継続動機
