# Python Quest - ブロック編集UI/UXレビュー

> Blocklyエディタのユーザビリティ特化レビュー
> URL: https://python-quest-three.vercel.app
> レビュー日: 2026-02-16
> レビュー方法: ソースコード精読 + 構造分析（BlocklyEditor.tsx, blocklyConfig.ts, quest/block/[id]/page.tsx）

---

## 総合評価

**B-（改善余地あり）**

MVP としての骨格はしっかりしており、Blockly の zelos レンダラー採用・ダークテーマ・日本語ロケール・スナップ半径拡大など、子供向けを意識した設計が見られる。しかし、**ブロック種類の少なさ（カスタムブロック2種のみ）**、**ツールボックスのカテゴリ設計の簡素さ**、**タッチデバイス対応の欠如**、**ワークスペースとコード表示の分断**など、教育プロダクトとして実用に供するには複数の重要な改善が必要。

---

## 1. ツールボックス

### 良い点
- 絵文字プレフィックス（📢📝🔢📦）でカテゴリを視覚的に区別している
- クエストごとに `availableBlocks` で表示カテゴリを制限し、認知負荷を下げている
- カテゴリの色分け（緑・青・黄・紫）が直感的

### 問題点

| 問題 | 深刻度 | 詳細 |
|------|--------|------|
| **カテゴリ名のフォントサイズ** | 中 | `fontStyle.size: 12` は小学生には小さい。最低14px、理想は16px |
| **ツールボックス背景色が暗すぎる** | 中 | `#12122a` はワークスペース `#1a1a2e` との差が小さく、境界が曖昧 |
| **フライアウトの透明度** | 低 | `flyoutOpacity: 0.95` — 背景が透けてブロック視認性が微妙に低下 |
| **カテゴリにアイコン画像がない** | 低 | 絵文字のみ。SVGアイコンの方が視認性・統一感が高い |
| **変数カテゴリが `custom="VARIABLE"` のまま** | 中 | Blocklyデフォルトの変数UIは「変数を作成...」ダイアログが英語混じりになりがち。日本語ロケール適用済みだが、子供には「変数を作成」の概念自体が難しい |

### 改善案
- `fontStyle.size` を **14〜16** に変更
- ツールボックス背景を `#0a0a20` 程度にしてコントラスト確保
- 変数カテゴリは `custom="VARIABLE"` ではなく、事前定義された変数ブロックを配置する方式に変更（クエスト7-8のみ使用なので、変数名をプリセットで良い）

## 2. ドラッグ＆ドロップ

### 良い点
- `snapRadius: 48`, `connectingSnapRadius: 68` に拡大済み — 子供のマウス精度を考慮した良い判断
- `grid.snap: true` でブロックがグリッドにスナップ
- zelos レンダラーは丸みのあるブロック形状で、接続部が視覚的に分かりやすい

### 問題点

| 問題 | 深刻度 | 詳細 |
|------|--------|------|
| **ドラッグ中のハイライトが地味** | 中 | `insertionMarkerColour: '#7c3aed'`, `insertionMarkerOpacity: 0.5` — 紫で半透明は暗い背景に溶け込む。もっと明るく、不透明に |
| **ブロック削除のUX** | 中 | trashcan は有効だが、子供が「ゴミ箱にドラッグ」を理解できるか不明。右クリック→削除もあるが右クリックは子供に馴染みが薄い |
| **フライアウトからのドラッグ距離** | 低 | ツールボックスが左端にあり、ワークスペース中央までの距離が長い。特にタブレットでは厳しい |
| **ブロック接続時のサウンドフィードバックなし** | 中 | `sounds: false` に設定されている。接続成功時のカチッという音は子供にとって重要なフィードバック |

### 改善案
- `insertionMarkerColour` を `#a78bfa`（明るい紫）、opacity を `0.8` に
- `sounds: true` に変更（Blockly標準のサウンドで十分）
- ゴミ箱アイコンを大きく、アニメーション付きに（ドラッグ中に口が開くなど）

---

## 3. ブロックデザイン

### 良い点
- カスタムブロックに絵文字ラベル（📢, 🔗）を付けて直感性を高めている
- ブロックのツールチップが子供向けの平易な日本語（「文字や数字を表示するよ」）
- 色分けが論理的（出力=緑、文字=青、計算=黄、変数=紫）

### 問題点

| 問題 | 深刻度 | 詳細 |
|------|--------|------|
| **カスタムブロックが2種類しかない** | 高 | `python_print` と `python_text_join` のみ。`math_number`, `math_arithmetic`, `text` はBlockly標準ブロックをそのまま使用。**標準ブロックのラベルは日本語ロケールだが、子供向けのフレンドリーさが欠ける** |
| **ブロックのフォントサイズ** | 中 | テーマの `fontStyle.size: 12` はブロック内テキストにも適用される。小学生には小さい |
| **入力フィールドの操作性** | 中 | テキストブロックのデフォルト値「こんにちは」は良いが、フィールドクリック時のテキスト選択・編集がBlocklyデフォルトのまま。IME（日本語入力）との相性が未検証 |
| **数値ブロックのデフォルト値** | 低 | `math_number` のデフォルトが `0` — クエスト5では `3 + 5` を作るので、`0` から変更が必要な点が小さなハードル |
| **ブロックの高さ** | 中 | zelosレンダラーのデフォルトサイズ。タッチ操作を考えると最小タップターゲット44px以上が理想 |

### 改善案
- `math_arithmetic`, `math_number` もカスタムブロック化し、絵文字ラベル＋子供向けツールチップを追加
- `fontStyle.size` を **14** に（ブロック内テキストの可読性向上）
- 数値フィールドのデフォルト値をクエストに応じてプリセット

## 4. ワークスペース

### 良い点
- グリッド表示あり（`spacing: 20, length: 3`）
- ズーム機能完備（`controls: true, wheel: true`, 0.5x〜2.0x）
- ゴミ箱有効
- ダークテーマがゲーム的雰囲気にマッチ

### 問題点

| 問題 | 深刻度 | 詳細 |
|------|--------|------|
| **ワークスペースの実質的な広さ** | 高 | デスクトップ: `md:grid-cols-[280px_1fr]` or `lg:grid-cols-[280px_1fr_1fr]` — サイドバー280px固定で、残りを2分割。1920px画面でもエディタは約820px幅。**モバイルではタブ切り替えで全画面だが、`minHeight: 400px` は制限的** |
| **グリッドの視認性** | 低 | グリッド色 `#1e1e3a` が背景 `#1a1a2e` とほぼ同色で、事実上見えない |
| **ズーム操作の初期説明なし** | 中 | ホイールズームやピンチズームが使えるが、子供にその操作を教えるUIがない |
| **ワークスペースの初期状態が空白** | 中 | 何もない空間は子供に「何をすればいいか分からない」感を与える |

### 改善案
- グリッド色を `#2a2a4a` 程度に変更して薄く見えるように
- ワークスペースに初期ブロック（コメントブロックで「ここにブロックを置いてね！」）を配置
- ズームコントロールボタンにツールチップ追加
- モバイルの `minHeight` を `500px` に増加

## 5. ブロック→コード→実行フロー

### 良い点
- ブロック変更時にリアルタイムでPythonコード生成（`workspace.addChangeListener`）
- 実行ボタンが目立つグリーングラデーション + グロー効果
- 実行結果の成否判定が自動（`normalizeOutput` で全角半角吸収）
- 失敗時のモーダルで期待値と実際の出力を比較表示

### 問題点

| 問題 | 深刻度 | 詳細 |
|------|--------|------|
| **コード表示が条件付き** | 高 | `{code && (...)}` — コードが空の時は非表示。初心者は「ブロックを置くとコードが出る」という発見が遅れる |
| **コード表示が `pointer-events-none`** | 低 | コードをコピーできない。教育的にはコードを触らせたい場面もある |
| **コード表示がエディタ下部に押し込まれている** | 高 | スクロールしないと見えない可能性。**ブロック→コードの対応を見せることが教育的核心なのに、コード表示の存在感が薄い** |
| **出力パネルがデスクトップでは `lg` 以上でのみ常時表示** | 高 | `md`（タブレット横持ち）では出力パネルが非表示で、モバイルタブと同じ切り替え式。**ブロック→コード→出力を同時に見られない** |
| **実行ボタンの位置** | 中 | エディタヘッダー右上。モバイルではタブ切り替えで「エディタ」タブにいないと見えない |
| **コード未入力時の実行ボタン無効化** | 低 | `disabled={!code.trim()}` — 適切だがビジュアルフィードバック（なぜ押せないか）がない |

### 改善案
- コード表示を常時表示（空でも「# ブロックを組み立てるとここにコードが表示されるよ」とプレースホルダー）
- コード表示エリアの高さを固定（`max-h-24 overflow-auto`）して常に見えるように
- タブレット（md）でも3カラムレイアウトを採用（サイドバーを折りたたみ式に）
- 実行ボタンをフローティングFAB化（モバイル時）

## 6. 子供目線での操作性

### 良い点
- ミッションイントロモーダルが魅力的（NPC絵文字アニメーション、スプリングトランジション）
- ヒントシステムが段階的（3段階）
- 失敗モーダルで「もう一度」「ヒントを見る」の選択肢
- クエストの段階設計（basic → practice → challenge）が適切

### 問題点

| 問題 | 深刻度 | 詳細 |
|------|--------|------|
| **初回操作のガイダンスがない** | 最高 | ミッションイントロ後、いきなり空のワークスペースが表示される。**「まずツールボックスからブロックをドラッグしてね」のようなステップバイステップガイドがない** |
| **タッチデバイス対応** | 高 | Blocklyは基本的にタッチ対応だが、**明示的なタッチ最適化（タップターゲットサイズ拡大、ロングプレス操作の説明等）がない** |
| **ダークテーマのコントラスト** | 中 | 全体的に暗い配色。子供は明るいUIの方が取っつきやすい。ScratchもCode.orgも明るい配色 |
| **エラーメッセージが技術的** | 中 | Skulptのエラーメッセージがそのまま表示される。子供には「うまくいかなかったよ。ブロックのつなげ方を確認してね」の方が適切 |
| **モバイルタブ切り替えの認知負荷** | 高 | 「情報→エディタ→出力」の3タブ切り替えは、小学生には「どこに何があるか」を記憶し続ける必要がある |
| **NPCダイアログの改行問題** | 低 | `whitespace-pre-line` で改行されるが、長いダイアログは読みにくい |
| **ブロック接続の「正解パターン」が分からない** | 高 | printブロックにtextブロックを入れる、という操作が初見では分からない。Value入力（ジグソーパズル型の穴）の意味を理解できるか |

### 改善案
- **チュートリアルオーバーレイ**の実装（最優先）：初回クエスト時に「①ツールボックスをクリック → ②ブロックをドラッグ → ③接続 → ④実行」をステップ表示
- エラーメッセージを子供向けにラップ
- モバイルではエディタ+出力の2画面構成に簡略化（情報はモーダルで表示済みなのでタブ不要）

## 8. 総括

### 強み
- **Blockly + zelos + ダークテーマ**の組み合わせはモダンで魅力的
- **クエストごとのブロック制限**は認知負荷管理として優秀
- **リアルタイムコード生成 + 自動判定**の仕組みは教育的に正しい
- **段階的ヒントシステム**は学習支援として適切
- **スナップ半径の拡大**は子供向け配慮として的確

### 最大の課題
1. **「初めて触る子供がブロックを組めるか？」に対する答えがNo** — チュートリアルガイドの欠如が致命的
2. **ブロック→コードの対応表示が教育的に活用されていない** — エディタ下部に追いやられ、存在感が薄い
3. **カスタムブロックが少なすぎる** — 標準Blocklyブロックとカスタムブロックのラベル品質に差がある

### 競合比較
- **Scratch**: ブロックが大きく、カテゴリが色分けされ、初回ガイドあり → Python Questは劣る
- **Code.org**: ステップバイステップのチュートリアルが秀逸 → Python Questに最も必要な要素
- **Blockly Games**: シンプルだがガイドが分かりやすい → 参考にすべき

### 結論
MVPとしての技術基盤は十分。**P0の3項目（チュートリアル、コード表示改善、ブロックカスタム化）を実装すれば、教育プロダクトとして実用に耐えるレベルに到達する。** 特にチュートリアルは「あったら嬉しい」ではなく「ないと使えない」レベルの必須機能。
