# 🛎️ FormShield — お問い合わせフォーム死活監視

## 概要
Webサイトのお問い合わせフォームが「壊れていても気づかない」問題を解決する。フォームが壊れると問い合わせがゼロになり、機会損失が発生するが、オーナーは「問い合わせが少ない時期かな」と放置しがち。FormShieldは定期的にフォーム送信をシミュレートし、送信失敗・メール未着を検知して即座にアラートを送る。

## ターゲットユーザー
- **中小企業のWeb担当者**: フォーム経由の問い合わせが売上に直結
- **フリーランスのWebデザイナー**: クライアントサイトのフォーム管理
- **ECサイトオーナー**: カスタマーサポートフォームの監視
- **不動産・クリニック等**: 予約フォームが生命線の業種

## ユーザーフロー
1. メールアドレスでサインアップ（10秒）
2. 監視したいフォームのURLを入力
3. FormShieldがフォームを自動検出し、テスト送信先メールを設定
4. 定期的にヘッドレスブラウザでフォーム送信をシミュレート
5. 送信成功→メール到着を確認（専用受信アドレスで検証）
6. 失敗時→即座にメール/Slack/LINE通知
7. ダッシュボードで稼働状況を確認
8. Freeプランの制限に当たったら有料プランへ

## アーキテクチャ
```
[ユーザー] → [Next.js on Vercel (フロント/API)]
                    ↓
            [Supabase (認証/DB)]
                    ↓
[EventBridge Scheduler] → [Lambda (Puppeteer)]
                    ↓
            [フォーム送信シミュレート]
                    ↓
        [SES受信 (専用ドメイン)] → 到着確認
                    ↓
            [未着検知] → [SNS → メール/Slack通知]
```

## 技術スタック
- **フロント**: Next.js (App Router) + Tailwind CSS
- **ホスティング**: Vercel (Hobby)
- **認証/DB**: Supabase
- **フォームテスト**: AWS Lambda + Puppeteer (chromium layer)
- **スケジューラ**: Amazon EventBridge Scheduler
- **メール受信**: Amazon SES (Receiving)
- **通知**: Amazon SNS → メール / Slack Webhook

## リスクと対策
| リスク | 対策 |
|--------|------|
| フォーム構造が多様でパース困難 | 主要フォームビルダー(Contact Form 7, Googleフォーム等)に対応。カスタムセレクタ設定も可能 |
| スパム判定されるリスク | テスト用の識別子を付与。ユーザーにホワイトリスト設定を案内 |
| Puppeteerのメンテコスト | Lambda Layerで管理。定期的にchromiumバージョン更新 |
| reCAPTCHA付きフォーム | reCAPTCHAテストキー設定をユーザーに案内。対応不可の場合はHTTPステータスのみ監視 |

## 競合分析
| サービス | 違い |
|----------|------|
| UptimeRobot | URL死活監視のみ。フォーム送信テストはしない |
| Freshping | 同上。HTTPレスポンス監視 |
| 手動テスト | 忘れる。月1回すらやらない |

**差別化**: 「フォームが動いているか」ではなく「フォームから送ったメールが届くか」まで検証する唯一のサービス。
