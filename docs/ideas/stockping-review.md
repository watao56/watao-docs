### 詳細レビュー

#### 🔴 致命的な問題

**1. ECプラットフォーム標準機能との競合**
- Shopify: 在庫切れ時のメール通知は標準機能（無料）
- BASE: 在庫アラート設定が標準搭載
- STORES: 在庫管理機能あり
- 各プラットフォームが自前で提供している機能を外部SaaSにわざわざ$5払う理由が弱い

**2. マルチプラットフォーム対応の開発コスト**
- 各EC APIの仕様が異なる。Shopify Admin API, BASE API, STORES APIのラッパーを個別開発
- API変更への追従コスト（継続的なメンテナンス）
- MVP 2週間でShopifyのみ→他は後回しだと、差別化の「マルチ対応」が当分使えない

#### 🟡 改善が必要

**3. 「在庫管理」は深い領域**
- 在庫アラートだけだと薄い。ユーザーは「在庫管理ツール」を期待する
- 発注タイミング提案、需要予測、仕入れ先連携...と機能要求がエスカレーションする
- 「アラートだけ」のツールに月$5はミスマッチ

**4. ECオーナーのITリテラシー**
- APIキー取得→入力の手順が非エンジニアには高いハードル
- Shopify App Storeでのインストール体験の方がはるかにスムーズ

#### 🟢 良い点

**5. 在庫切れ=売上損失の訴求は明確**
**6. AI不使用でコスト$0.15/月は素晴らしい**
**7. EC市場の成長トレンド**

### 改善提案

1. **Shopify App特化**: Shopify App Storeに特化して、インストールワンクリックの体験にする
2. **在庫切れ予測**に価値を移行: 「あと3日で在庫切れ」の予測アラートなら標準機能にない価値
3. **マルチチャネル在庫同期**: 実店舗+EC+Amazonの在庫を一元管理する方向（ただし開発コスト大）
4. **「安い仕入れ先アラート」とセット**: 在庫低下時に仕入れ先の最安値を通知

### 結論

課題は本物だが、**各ECプラットフォームが標準で在庫アラートを提供している**ため、外部SaaSとしての存在意義が薄い。Shopify App Storeに特化して「在庫切れ予測」や「マルチチャネル同期」に価値を寄せないと、$5/月の正当化は難しい。
