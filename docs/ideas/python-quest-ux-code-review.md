# Python Quest - UI/UX・コードレビュー

> シニアUI/UXエンジニアによる厳格レビュー
> URL: https://python-quest-three.vercel.app
> レビュー日: 2026-02-17
> ソースコード: /home/node/clawd/python-quest/src/

## 総合評価: B（MVPとしては合格、プロダクトリリースには不足）

MVPとしての基本機能は揃っているが、UI品質・アクセシビリティ・コード設計に複数の深刻な問題がある。子供が一人で使うプロダクトとしては、もう1〜2スプリント分の改善が必要。

---

## 1. UI品質

### 良い点
- ダークテーマの世界観が統一されており、ゲーム感がある
- グラデーション・グロウエフェクトの使い方がRPG風でターゲットに合っている
- 絵文字を効果的にアイコン代わりに使っており、追加アセット不要で視覚的に伝わる
- `Press Start 2P` フォントのアクセント使いは適切
- ClearModalの紙吹雪アニメーション・CountUpは達成感を演出できている
- XPバーのシマーアニメーションは高品質

### 問題点（深刻度付き）

#### 🔴 Critical
1. **コントラスト比がWCAG AA不適合（複数箇所）**
   - `text-slate-500` (#64748b) on `#0a0a1a` → コントラスト比 約3.2:1（AA要件 4.5:1に不適合）
   - `text-[#4a4a6a]` on `#0a0a1a` → 約2.0:1（完全に不適合）
   - `text-[#333]`のロックアイコン → ほぼ見えない
   - NPCダイアログの `text-purple-200` は読みやすいが、`text-slate-500` の説明文は子供には読みにくい
   - **影響**: 視力の弱い子供、明るい部屋でのモニター使用時に致命的

2. **フォントサイズの不統一・小ささ**
   - ワールドマップのスター表示 `text-[8px]` → 子供には完全に読めない
   - XPバーの情報が `text-sm` (14px) で小さすぎる
   - クエストノードのテキスト `text-sm` → タップターゲットは12x12だが表示テキストが小さい

#### 🟡 Major
3. **`animate-pulse`の使い方が不適切**
   - 利用可能クエストノードに `animate-pulse` を使用 → 常時点滅はアクセシビリティガイドライン違反（`prefers-reduced-motion` 未対応）
   - てんかん誘発リスクは低いが、注意散漫の原因になる

4. **CTA「冒険をつづける」ボタンの常時スケールアニメーション**
   - `scale: [1, 1.05, 1]` が永続的に繰り返される → 落ち着きがなく、UIの品質を下げる
   - 初回注目を引いた後は停止すべき

5. **フライアウト幅のハードコード**
   - `max-width: 200px !important` で強制制限 → ブロック名が切れる可能性がある
   - `!important` 乱用（globals.cssに4箇所）

#### 🟢 Minor
6. **ロック済みワールドの `opacity: 0.35`**
   - 情報としては読ませたいが、opacity 0.35は低すぎる。0.5〜0.6が適切

7. **レスポンシブブレークポイントのギャップ**
   - `md` と `lg` でレイアウトが大きく変わる（2カラム → 3カラム）が、中間状態の考慮不足
   - タブレット横向き（1024px付近）で出力パネルが突然現れる

### スコア: C+（コントラスト問題が深刻）

## 2. UX品質

### 良い点
- ミッションイントロモーダルでクエスト開始前にNPCが説明 → 文脈設定が良い
- チュートリアルのステップインジケーター（ドット表示）が分かりやすい
- FailModalの段階的メッセージ（試行回数に応じた励まし）は教育的に優秀
- diff表示で期待値と実際の出力を並べる → 何が間違っているか視覚的に分かる
- エラーメッセージの日本語化が丁寧（15パターン対応）
- ワールドマップ → クエスト → クリア → 次のクエストの導線が明確
- 正解判定のnormalize処理（全角半角変換）が子供の入力ミスに寛容

### 問題点（深刻度付き）

#### 🔴 Critical
1. **モバイルでのBlocklyエディタ操作性**
   - タブ切り替え式UIで、エディタと出力を同時に見られない
   - ブロックを組み立てた後、出力タブに切り替えて確認、またエディタに戻る → 認知負荷が高い
   - Blocklyのタッチ操作（ピンチズーム・ドラッグ）とページスクロールの競合未対応
   - **小学4年生がスマホで使うケースを考えると致命的**

2. **チュートリアルがクエスト1-1でしか表示されない**
   - `localStorage`ベースで一度完了すると二度と表示されない
   - リセット手段がUI上にない
   - 新しいブロック種類（結合、計算、変数）が登場するクエストでの追加チュートリアルがない

3. **「もう一度」の体験が不親切**
   - FailModal閉じた後、ブロックはそのまま → 何を直せばいいか分からない
   - エラー箇所のハイライトやブロックへの視覚的フィードバックがない

#### 🟡 Major
4. **戻るボタンの発見困難性**
   - 「← マップに戻る」がサイドバー最下部の `text-slate-500` → 見つけにくい
   - ブラウザバックに依存するユーザーが多いはず（子供は特に）
   - ヘッダーに常時表示すべき

5. **クリア後の自動遷移がない**
   - ClearModal表示後、ユーザーが「次のクエストへ」を押さないと進めない
   - 子供は達成感で興奮しているときに次のアクションを忘れがち

6. **コイン（coins）の使い道が不明**
   - コインを獲得するがUIに表示されない（XPバーにも、マップにもない）
   - 報酬として表示されるが使えない → 期待を裏切る

7. **Skulpt CDN依存のリスク**
   - `skulpt.org` からの外部スクリプト読み込み → CDNダウン時にアプリ完全停止
   - ローディング状態の表示がない（skulptReady=falseの間、実行ボタンがdisabledなだけ）
   - 子供には「なぜ押せないの？」が分からない

8. **サイドバー折りたたみ時のアイコンのみ表示**
   - 📋🎯💡 のアイコンだけでは何ができるか分からない
   - tooltip もない

#### 🟢 Minor
9. **ヒントボタンがFailModal内にしかない**
   - 失敗する前にヒントを見たい子供がいるはず
   - サイドバーにヒントボタンを常時表示すべき

10. **クエスト選択時のステータス表示不足**
    - クリア済みクエストを再プレイできるが、そのことが伝わらない

### スコア: C+（モバイル体験とチュートリアル不足が深刻）

## 3. コード品質

### 良い点
- **Zustand + persist** の選択は適切。教育アプリの進捗保存にぴったり
- `partialize` でストアの永続化対象を絞っている
- SSRハイドレーション対策（`mounted` state）を意識している
- `normalizeOutput` で全角半角を吸収 → 実用的
- TypeScriptの型定義が概ね適切（Quest, QuestProgress, GameState）
- `dynamic import` でBlocklyをSSR回避
- エラーメッセージの翻訳パターンが拡張しやすい設計

### 問題点（深刻度付き）

#### 🔴 Critical
1. **QuestPageの巨大コンポーネント（約250行）**
   - 状態が11個（useState x 11）→ 責務過多
   - ミッションイントロ、チュートリアル、エディタ、出力、サイドバー、モーダル2種が1コンポーネントに
   - テスト不可能、メンテナンス困難
   - **分割案**: `QuestSidebar`, `QuestEditor`, `QuestModals`, `MissionIntro` に分離すべき

2. **`handleRun` 内でのストア直接呼び出し（レンダリング中の状態読み取り）**
   - `getQuestProgress` をイベントハンドラ内で呼んでいるが、クロージャの問題でstale stateになる可能性
   - `clearQuest` の直後に `getQuestProgress` → 更新が反映されない可能性

3. **Skulptの`window.Sk`直接参照**
   - グローバル変数汚染
   - TypeScript的に `declare global` で逃げているが、型安全性ゼロ
   - Skulptの読み込みエラー時のリカバリがない

4. **pythonRunner.tsにerrorMessages.tsの内容が重複**
   - `translateError` が `errorMessages.ts` に定義されているが、`pythonRunner.ts` にも同じパターン配列がコピペされている → 二重管理

#### 🟡 Major
5. **BlocklyEditorの`onCodeChange`コールバック**
   - 親から渡される `handleCodeChange` は `useCallback` だが、依存配列が空 → 問題ないが、将来的にバグの温床
   - BlocklyのchangeListenerが高頻度で発火 → デバウンスなし
   - 毎回 `generatePython` が走る → パフォーマンス懸念

6. **`@ts-expect-error` の使用**
   - `flyoutAutoClose` に対して型エラーを抑制 → Blocklyの型定義更新で壊れるリスク
   - `(flyout as any)`, `(Blockly as any)` が複数箇所 → 型安全性の放棄

7. **CSSの `!important` 乱用**
   - globals.css内に `!important` が7箇所
   - Blocklyのスタイル上書きに必要だが、コメントで理由が書かれていない
   - より良い方法: Blocklyのテーマ設定で対応可能な箇所がある

8. **アクセシビリティ属性の完全欠如**
   - `aria-label`, `aria-live`, `role` が一切ない
   - クエストノードボタンにラベルなし → スクリーンリーダーでは「ボタン 1」としか読まれない
   - モーダルに `role="dialog"`, `aria-modal="true"` なし
   - キーボード操作: Escでモーダルを閉じられない
   - フォーカストラップなし

9. **`useEffect` の依存配列問題**
   - BlocklyEditor: `availableBlocks` が配列なので、親が再レンダリングするたびに新しい参照 → Blockly再初期化のリスク（実際にはrefチェックで防がれているが偶然）

#### 🟢 Minor
10. **コンポーネントファイルの整理不足**
    - `components/` 直下にフラットに配置 → 機能別ディレクトリ（`components/quest/`, `components/modals/`）に分けるべき

11. **マジックナンバー**
    - `setTimeout(() => setShowClear(true), 2500)` の2500msが定数化されていない
    - XPバーの `Math.min((xp / 100) * 100, 100)` → 100がレベルテーブルと無関係のハードコード

12. **Press Start 2P フォントのGoogle Fonts読み込み**
    - `<head>` 直接 → Next.jsの `next/font` を使うべき（パフォーマンス最適化）

13. **テストの不在**
    - テストファイルが1つもない
    - `normalizeOutput`, `translateError`, ストアのロジックは単体テスト必須

### スコア: C（巨大コンポーネント・アクセシビリティ欠如・テストなし）

## 4. 子供向けプロダクトとしての評価

### 良い点
- RPGメタファー（クエスト、ワールド、レベル、XP）は小学生に馴染みやすい
- ブロッくんのキャラクター性があり、対話形式のガイドは効果的
- ヒントが段階的に表示される仕組みは教育的に正しい
- 失敗時の励ましメッセージが試行回数に応じて変化 → 挫折防止
- エラーメッセージの日本語化が丁寧で、子供でも理解できる表現
- クエスト設計がprint → 文字結合 → 計算 → 変数と段階的

### 問題点

#### 🔴 致命的
1. **「何をすればいいか分からない」瞬間が多すぎる**
   - チュートリアルが初回のみ。クエスト1-3で「結合ブロック」が初登場するが説明なし
   - NPCのダイアログだけでは、Blocklyの操作方法（ドラッグ→接続→値入力）を理解できない
   - **対策**: 各クエストの新概念にインタラクティブチュートリアルが必要

2. **ダークテーマ固定**
   - 子供向けアプリでダークテーマ固定はリスク
   - 明るい教室、保護者と一緒に見る場面 → 暗い画面は不自然
   - ライトテーマオプションまたは明るめダークが望ましい

3. **保護者機能の不在**
   - 進捗確認、使用時間、リセット機能がない
   - localStorage依存でデバイス間同期なし

#### 🟡 重要
4. **報酬システムの未完成**
   - コインの使い道がない → 集める動機がない
   - スター3つの条件が不透明（ヒント0回＆1回で正解）→ 子供には分からない
   - レベルアップの演出がない（静かにレベルが上がる）

5. **ゲームオーバーがない（良い面もある）**
   - 無限リトライ可能は教育的に良いが、チャレンジ感が薄い
   - 時間制限や「残りHP」のような緊張感の仕組みがあると良い

6. **クエスト数が少なすぎる（8問）**
   - ワールド1のみで完結 → 30分〜1時間で終わる
   - 終わった後の「次にやること」がない

### スコア: B-（基本的な教育設計は良いが、自立学習には不十分）

## 6. 総括

### MVPとしての評価
Python Questは**MVPとしての最低限の機能は達成している**。ブロックプログラミング→Python変換→実行→正解判定の基本ループが動作し、8つのクエストで段階的学習ができる。RPG風のUIとキャラクター（ブロッくん）による対話的ガイドは、子供向けプロダクトの方向性として正しい。

### プロダクトリリースとしての評価
**現状ではリリース不可**。以下が主な理由:

1. **アクセシビリティの完全欠如** — 教育プロダクトとして、WCAG AA準拠は最低ライン。aria属性ゼロ、コントラスト不適合は公開NGレベル
2. **モバイル体験の貧弱さ** — 子供のメインデバイスがスマホ/タブレットであることを考えると、タブ切り替え式UIは致命的
3. **自立学習の壁** — チュートリアルが初回のみで、新概念導入時のガイダンスがない。小学4年生が一人で使うには不十分
4. **コード品質** — 250行の巨大コンポーネント、テストゼロ、型安全性の放棄箇所が多く、チーム開発やメンテナンスに耐えない

### ポテンシャル
設計思想は良い。RPGメタファー、段階的ヒント、子供向けエラーメッセージ翻訳、全角半角正規化など、**ユーザーへの思いやりが感じられる設計判断**が随所にある。P0改善（推定10h）を入れればβリリース可能、P1改善（推定28h）を入れれば正式リリース可能なレベル。
