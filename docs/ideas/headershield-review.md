## 良い点

### 1. SecurityHeaders.comの「監視版」という明確なポジション
SecurityHeaders.comは月間数百万ユーザーがいるが、1回限りのチェックツール。「定期監視+アラート」版は存在しない。確立されたニーズの延長線上にある。

### 2. 技術的シンプルさ
HTTP HEADリクエスト→レスポンスヘッダー解析→スコアリング。Puppeteerもブラウザも不要。Lambda実行時間100ms以下。

### 3. 修正ガイドという付加価値
「問題を見つける」だけでなく「どう直すか」をnginx/Apache/Cloudflare別にコピペ可能な形で提供。これはSecurityHeaders.comにはない。

### 4. コンプライアンス需要
PCI DSS、SOC2等のセキュリティ監査でHTTPヘッダーは必ずチェックされる。監査レポートとして使える=B2B価値。

### 5. 無料ツール→有料転換の自然なパス
「あなたのサイトのスコアは？」でバイラル→継続監視したい人がPro契約。ファネルが自然。

## 懸念点と改善提案

### 1. セキュリティヘッダーの認知度（中程度）
開発者でも「CSP? HSTS? 何それ？」という人は多い。教育コストが必要。
→ **対策**: 無料スコアチェックツールを前面に出し、スコアFの人に「改善しませんか？」でアップセル。設計書のマーケ計画Phase 1が適切。

### 2. CDN/WAFが自動付与するケース
CloudflareやAWS CloudFrontが一部ヘッダーを自動付与する場合、オリジンサーバーの設定と混同する可能性。
→ **対策**: 「CDN経由」と「直接アクセス」の両方をチェックし、差異を表示する機能。

### 3. 「設定したら終わり」でチャーンする可能性
セキュリティヘッダーは一度正しく設定すれば変わらない。改善後に「もう不要」と解約されるリスク。
→ **対策**: 「デプロイ/CDN変更で壊れることがある」「保険として継続」を訴求。月$5なら解約する手間の方が大きい。
