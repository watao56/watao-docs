## 良い点

### 1. 課題が明確で巨大
インバウンド3,600万人超という追い風は本物。外国人観光客の「メニューが読めない」は体験上のペインポイント第1位クラス。飲食店側も「英語メニュー作りたいけど面倒/高い」という明確な課題を持つ。

### 2. 参入タイミングが最高
- 2025年のインバウンド新記録更新
- 2025年アレルゲン表示義務化の動き
- まだ「写真→多言語メニュー」を低価格で提供するプレイヤーがいない

### 3. ユニットエコノミクスが健全
- LTV/CAC 17.8xは非常に優秀
- AI費用が初回のみで継続課金に対して限界費用がほぼゼロ
- 粗利95%超

### 4. マーケティングがオフラインで差別化
飲食店へのアプローチがチラシ+直接訪問という「泥臭い」手法は、むしろ競合が真似しにくい。SaaS企業はデジタルマーケばかりやるので。

## 懸念点と改善提案

### 1. 飲食店オーナーのIT障壁（中リスク）
**懸念**: 個人経営の飲食店オーナーはスマホ操作に不慣れな場合が多い。
**対策済み**: LINE連携と動画チュートリアルの計画あり。
**追加提案**: 初回セットアップ代行（無料/有料）を用意し、「写真送るだけでこちらで作ります」という完全お任せプランも検討。

### 2. OCR精度（中リスク）
**懸念**: 手書き和風メニュー、縦書き、かすれた印刷のOCR精度。
**対策済み**: 手動補正UI。
**追加提案**: GPT-4oのマルチモーダル機能で「メニュー画像→直接構造化」を試すのも手。Vision APIより精度が高い可能性あり。コスト的にもGPT-4o-miniでメニュー1枚$0.01程度なら問題ない。

### 3. チャーンリスク（低リスク）
**懸念**: 一度メニューを作ったら解約する可能性。
**対策**: Pro限定のアクセス解析、季節メニュー更新機能、「人気メニューランキング」等の継続価値を提供。QRコードがSnapMenuドメインなので解約=QR無効化が自然なロックイン。

### 4. Googleレンズとの競合（低リスク）
**懸念**: 無料のGoogleレンズで十分では？
**反論**: Googleレンズは「その場限り」「店のブランド感ゼロ」「写真なし」。SnapMenuは店の常設デジタルメニューとして機能し、全く別のポジション。

## 技術評価

- **アーキテクチャ**: Vercel + Supabase構成は適切。CDNでメニュー配信するのでレスポンスも速い
- **DB設計**: 正規化されており問題なし。JSONB翻訳はスキーマレス拡張に便利
- **コスト見積もり**: 妥当。Vision API無料枠1000リクエスト/月は初期には十分
- **MVPスコープ**: 2週間は攻めているがNext.js + Supabaseなら可能

## $20達成の現実性

**達成可能性: 高**

観光地の飲食店に直接アプローチできるのが強み。浅草だけで飲食店数百軒、英語メニューがない店は半数以上。チラシ50枚配って5%転換なら2.5店、これを数エリアでやれば2ヶ月で到達する計算。

## 総合判定: A

インバウンド需要という巨大な追い風、明確なペインポイント、低コスト構造、オフラインマーケの差別化。$20どころか$200も十分狙えるポテンシャルを持つ。唯一の不安要素はターゲット層のITリテラシーだが、LINE連携とセットアップ代行で十分カバー可能。
